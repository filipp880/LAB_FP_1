# Лабораторная работа №1 — резервное хранилище

Полное объяснение проекта простыми словами — в [РАЗБОР_ПРОЕКТА.md](РАЗБОР_ПРОЕКТА.md).
В исходниках оставлены короткие комментарии к важным функциям и неочевидным решениям.

Рефакторинг ЛР0 из `filipp880/Lab_FP`, исходный коммит `c348211`.
Scala 3.7.4, Java 17, одна внешняя библиотека — uPickle/uJson для JSON.

## Запуск

Открой терминал в этой папке:

```powershell
scala-cli run . --server=false --main-class backup.backupApp
```

На Windows можно запустить `run.cmd`. При первом запуске Scala CLI скачает
Java 17 и зависимости, если их ещё нет. Создаются `backup.json`, `backup.log`
и каталог `keys`. Пути из конфигурации считаются относительно текущей папки.

Сборка через sbt также сохранена: `sbt run` (нужна Java 17 или новее).

## Как пользоваться

Главное меню показывает русские пункты: достаточно вводить их номера.
Пункт 4 открывает отдельное меню источников с добавлением, изменением,
удалением и включением копирования. В вопросах можно отвечать `1` (да),
`2` (нет), русскими словами или нажимать Enter для указанного варианта.
При ошибке выбора папки программа повторяет вопрос. Кириллица читается
через кодировку терминала Windows, а в окне запуска IDEA — как UTF-8.
Английские команды также поддерживаются:

1. `create` — выбрать устройство по номеру или ввести каталог, задать имя,
   выбрать шифрование и первоначальные источники.
2. `sources` — список источников; `sources add`, `sources edit 1`,
   `sources disable 1`, `sources enable 1`, `sources remove 1` — настройка.
3. `scan` — показать изменения; `backup комментарий` — подтвердить и сохранить.
4. `versions` — список снимков; `restore 1` — восстановить первый снимок,
   `restore` — выбрать снимок (Enter — последний). Каталог назначения запрашивается отдельно.
5. `verify` — проверить данные, `reload` — перечитать конфигурацию,
   `info` — сведения, `help` — команды, `exit` или `0` — выход.

`open` открывает указанный файл контейнера, в том числе на другом устройстве.
Для зашифрованного контейнера введи ключ; Enter загружает сохранённый `.key`.
Существующий контейнер при `create` не перезаписывается — выбери другое имя.
При восстановлении ответ «нет» пропускает существующий файл, «да» заменяет его.
Если подтверждение перезаписи отключено в конфигурации, файл заменяется сразу.
Файлы разных источников восстанавливаются в подпапки `s0`, `s1`, …,
чтобы одинаковые имена не конфликтовали.

## Что изменено для ЛР1

- `Command.scala`: `enum Command` и `SourceAction`. Ввод разбирается один раз,
  затем выполняется типизированная команда.
- `AppError.scala`: ADT причин ошибок. Операции возвращают
  `Either[AppError, A]`. Текст сообщения хранится в самой ошибке, поэтому
  отдельный повторяющийся `match` для вывода не нужен.
  Ошибки Java API преобразуются в `Left` на границе.
- Текущее хранилище, ключ, комментарий, последняя версия и удалённый файл
  представлены через `Option`, без фиктивных значений.
- `Menu.scala` содержит диалоги, вывод и подтверждения. `Container`, `Scanner`,
  модели и конфигурация не читают консоль и не печатают сообщения.
- `map`, `flatMap`, `filter`, `collect` и for-comprehension используются
  для преобразования коллекций и результатов. Циклы оставлены для ввода и IO.
- Удалены самописный JSON-парсер и дублирующий слой `Engine`.
  Используется простое меню с номерами и текстовыми командами.
- Самописный XOR заменён стандартным AES-GCM из Java. Ключи не записываются
  в журнал; каталог ключей и служебные файлы исключаются из копии.
- Исправлены повторяющиеся ZIP-записи, обработка одиночного файла-источника,
  пропуски при ошибках чтения и изменении файла, замена контейнера через
  временный файл и проверка данных перед перезаписью при восстановлении.
  Запись контейнера и восстановленного файла используют одну небольшую функцию
  замены файла. Стандартный `Using.resource` закрывает потоки автоматически.

Дополнительно удалены неиспользуемые JSON-обёртки и промежуточные коллекции.
Последняя версия находится через `maxByOption`, конфигурация разбирается один раз,
а первоначальные источники собираются без нескольких изменяемых флагов.

После сверки с `Task1.txt` и `Task3.md` убраны неиспользуемые параметры
восстановления и проверки, лишние методы журнала, неиспользуемая карта файлов
в плане копирования и повторная проверка доступности источников.
Обход родителей пути записан обычным циклом с `Option`.
Замена файла каталогом и обратно корректно отражается в снимках.
Отключение источника после проверки не считается удалением его файлов,
а дата успешной копии обновляется отдельно для каждого источника.
Ошибки команды `scan` записываются в журнал без пользовательского ввода.
Если файл конфигурации исчез, `reload` сообщает об ошибке и сохраняет прежние настройки.

Ошибку обрабатывает ближайший уровень, который может решить, что делать:
CLI повторяет неправильный ответ да/нет, сообщает о неверной команде или ключе,
а ошибка отдельного файла попадает в отчёт и не останавливает остальные файлы.
State/IO, собственные классы типов и дополнительные архитектурные слои не нужны.

## Версии и совместимость

Лимит применяется к старому содержимому каждого файла. Последнее содержимое
сохраняется. Если старый снимок частично очищен по лимиту, это видно в `versions`
и перед восстановлением. Отключённый или недоступный источник не считается удалённым.

Незашифрованные контейнеры ЛР0 читаются. Старые контейнеры с самописным XOR
нужно восстановить программой ЛР0 и сохранить заново через ЛР1.
В новом формате шифруется содержимое файлов; метаданные ZIP остаются открытыми.
Для простоты изменённые файлы загружаются в память, как в исходной ЛР0.

## Проверки

```powershell
scala-cli run . --server=false --main-class backup.backupChecks
```

`tests/BackupChecks.scala` содержит 24 группы проверок полного цикла копирования и восстановления,
JSON и конфигурацию, версии, дедупликацию, ошибки, AES и защиту ключей.
Проверки используют отдельную временную папку и не меняют пользовательские данные.
